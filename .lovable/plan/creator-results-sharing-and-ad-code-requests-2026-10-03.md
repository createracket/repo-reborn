# Creator results sharing and ad-code requests

## Outcome
Creators can opt in to connecting their Instagram or TikTok accounts so eligible post results can be brought into report review. Separately, each live post can have its own ad-code request: send an editable email or copy a private link, collect the creator's TikTok Spark Ads code or Instagram partnership-ad code/permission, and review it without mixing it into the stats request.

## 1. Creator account connection
- Add a **Connect Instagram / Connect TikTok** area to a signed-in creator's profile. Explain exactly what Racket will read, show connection status and last sync, and provide disconnect/revoke controls. Connecting is optional; the existing screenshot/stat-request flow remains available.
- Use each platform's own creator-authorized connection, not social sign-in, saved URLs, public profile scraping, or the admin's account. Bind access to the signed-in user; keep provider credentials and tokens server-side, encrypted/protected, with refresh and revocation handling. Only match a report post when its URL belongs to the connected account. Never let a creator's connection read another creator's report data.
- Add an admin-facing **Sync connected results** action per matching post, alongside the existing stats-request action. Bring supported metrics into a review state with source and sync timestamp; admin confirms before the report changes. Preserve manual entries unless explicitly approved, and display unavailable metrics as unavailable rather than zero. Reuse existing request-by-link/screenshot flow where the platform does not supply a metric.
- Start with Instagram professional accounts (Business/Creator) and TikTok accounts where their approved API scopes support the post metrics. Check platform app review, approved permissions, real-account eligibility, and exact metrics in a small pilot before offering automatic sync broadly; if an account or metric isn't eligible, show a clear fallback rather than claiming full private analytics. Do not promise automatic updates before these approvals are complete.

## 2. Separate per-post ad-code requests
- Add **Request ad codes** beside **Request stats** on each live post in the detailed report builder. Open a separate editable draft with platform-aware wording, creator email, the existing post link, and a **Send request** or **Copy link only** choice; let the admin later copy the same link again.
- Give each request its own high-entropy, no-login, no-index link. The creator sees the specific post and can submit a TikTok Spark Ads authorization code with its expiry/authorization period, or an Instagram partnership-ad code or confirmation of content-level permission, plus a note. Keep instructions specific to each platform. Permit corrections until admin marks the response reviewed; allow a new request if the code expires.
- Send the creator the ad-code email and a **separate private copy** to community@createracket.com, with replies going there. Notify community@ when a response arrives. A copied link sends no email. Keep ad codes out of public report pages, exports, notification previews and email bodies; show them only in the admin review with controlled copy-to-clipboard. Do not treat a supplied code as automatic permission for other posts, platforms or uses.
- Show Requested / Viewed / Submitted / Reviewed status and the code or permission, expiry and note in the report builder. Store these in a separate admin-protected request record; the token-gated creator page can only read or update its own request. Do not change post metrics or the stats-request status when an ad code is submitted.

## Technical approach and dependencies
- The current profile **Sync** reads public social links; it is not creator-authorized access to private post insights. The current `/stats/<token>` request and email-copy flow can guide the new UI, but ad-code data and templates stay separate.
- This workspace has no Instagram or TikTok **per-user** connector available. Account connections therefore require a dedicated platform OAuth integration with securely stored per-user credentials and provider app registrations/approvals; do not substitute the workspace TikTok connector, which would connect one workspace-owned account. Confirm provider permissions in the pilot and make unavailable states explicit.
- Meta documents Instagram professional-media insights and Advanced Access for accounts outside the app owner's organization ([Meta insights](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-facebook-login/insights)); TikTok's documented user video object exposes views, likes, comments and shares ([TikTok video object](https://developers.tiktok.com/doc/tiktok-api-v2-video-object)), but richer private insights must be validated per approved product. TikTok Spark Ads use post authorization codes ([TikTok guidance](https://ads.tiktok.com/resources/help/article/how-to-create-spark-ads-for-smart-campaigns-on-tiktok-ads-manager)); Instagram partnership ads support per-content codes or boost permissions ([Meta guidance](https://www.facebook.com/business/help/354752406906368)).
- Use the existing verified Racket email domain and managed email delivery for the ad-code request and response notices. Migration for the separate request table must include explicit grants and admin-only policies. Put server-only OAuth/API access behind authenticated server functions and a verified external callback route; no secrets in client code or URL query strings.

## Checks
- Test a signed-in creator's connect, disconnect, wrong-account match, permission denial and expired connection; verify real eligible post metrics appear in admin review and not automatically on the public report. Test the no-login ad-code link, email and community copy, copy-link-only, invalid/expired token, correction, and admin-only visibility on desktop and mobile. Complete a real provider sandbox/pilot before calling creator syncing live.
